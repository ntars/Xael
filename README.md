> 玄之又玄，众妙之门。
>
> 演乾坤 · 知天命。

## 一、项目名称与定位

**名称**：玄玖灵犀 Xael。「玄玖」取自「玄之又玄」，亦为工作室「星玖」之玖；「灵犀」取「心有灵犀」，指推算结果能与文献原意相通。

**一句话定位**：一个把中华术数从历法底座到排盘结论全部自行演算的本地离线文献库，结果可复核、口径可查证、代码可通读。

**定位的三条边界**：

1. **它是文献工具，不是算命服务**。给出结论的同时必须给出依据（哪部书、哪一篇、什么条件）；给不出依据的条目不生成。
2. **它是本地程序，不是在线接口**。不联网、不调用任何第三方术数 API、不上传生辰数据。断网可用是硬性要求。
3. **它是可校勘的底本，不是不可质疑的黑箱**。所有流派选择写在 `docs/CALIBER-NOTES.md`，任何人可以按自己的口径改一处表来换派。

## 二、项目简介

### 2.1 背景

术数软件长期是两极。一极是闭源商业排盘站：算法不透明、口径不可查、离线不可用，用户只能选择信或不信。另一极是零散开源脚本：单点功能（只排八字、只排奇门）、没有统一历法底座、出问题无从复核，作者往往也只跑通了几个样例。

想认真读、认真核、认真改的人，几乎没有可站的地面。

### 2.2 要解决的问题

三个硬骨头：

1. **历法**。农历必须靠真朔日与真节气。查表法在边界日必错，而边界日恰恰是最需要准确的日子（闰月归属、交节换月）。任何依赖历表的实现，在 1900 年前后与未来年份都会失效。
2. **口径**。紫微四化、奇门定元、六壬发用各派并存，混用即错。同一张盘用不同口径排，结论可以完全相反，而软件若不声明口径，用户无从判断结果属于哪一派。
3. **可验证性**。给出结果却给不出依据，等于无法校验。术数结论若不能回溯到文献原文，它就只是一个说法，不是一个可检验的推论。

### 2.3 核心思路

把「天文历法」和「术数规则」严格分层：

| 层 | 位置 | 职责 | 不做什么 |
|---|---|---|---|
| 历法层 | `src/core/calendar/` | 用天文级数实时求太阳黄经、日月合朔与节气时刻 | 不含任何术数规则 |
| 规则层 | `src/core/four-pillars/`、`purple-star/`、`mystic-gates/` 等 | 只消费标准化的干支与节气数据 | 不自己算历法 |
| 端壳层 | `miniprogram/`、站点根目录、`uni-app` | 只负责交互与渲染 | 不含任何算法 |

历法层不依赖任何历表：公历 → 儒略日 → 太阳黄经（VSOP87 截断级数 + 章动/光行差/ΔT）→ 日月合朔（1985 年前走寿星精密朔表 SHUO_KB，之后走级数）→ 朔日定月 → 两冬至间无中气置闰。

### 2.4 适用场景

- 术数研究者的文献校对与手工排盘复核；
- 开发者集成（生辰 → 八字、节气提醒、黄历数据）；
- 传统历法教学（可逐层看到每一步的中间结果）；
- 需要自建透明内核的产品。

### 2.5 非目标

- 不做吉凶预测的「准确率」承诺：本项目给的是按特定口径推出的结论，不是对未来的断言。
- 不做命理咨询：没有解读服务、没有大师背书。
- 不做云端账号：没有用户体系、没有历史记录同步。
- 不收录无文献依据的条目：宁缺不臆造。

## 四、算法详解

本章逐个介绍八个门类、22 项功能。每项给出五件事：**依据哪部文献的哪一篇**、**算法怎么算**、**能给出什么结果**、**流派分歧怎么处理**、**证据强度属于哪一档**。

三档强度先说明白，后文每项只标档位：

| 档 | 含义 | 判定方式 |
|---|---|---|
| **A 原书直证** | 规则与断语都能在库内 `refs-texts/` 底本正文找到对应句子 | `npm run check:cites`（篇名可回溯）与 `npm run check:readings`（断语逐子句可回溯）强制校验 |
| **B 结构自洽** | 底本给了结构关系，但绝对起点原书自云「不可得而考」 | 输出写明「结构自洽、锚点不可考」 |
| **C 库外/通行** | 库内 20 部无载，取近世整理或通行口诀 | 输出与文档明标「库外」「近世整理」「待考」 |

**库内 20 部底本**（`refs-texts/`，均为公版古籍）：《周易》《渊海子平》《滴天髓》《子平真诠》《三命通会》《穷通宝鉴》《紫微斗数全书》（两版）《奇门遁甲统宗》《奇门宝鉴》《遁甲演义》《六壬大全》《大六壬指南》《壬归》《毕法赋》《卜筮正宗》《增删卜易》《黄金策》《梅花易数》《钦定协纪辨方书》《御定星历考原》《玉匣記》。

### 4.1 历法底座：一切推算的地基

历法不是一项功能，而是全部 22 项功能的共同前提。它错了，上面所有排盘都会错。

#### 4.1.1 依据

| 内容 | 出处 |
|---|---|
| 天文级数与常数 | 库外 Jean Meeus《Astronomical Algorithms》第二版（算法思想不受版权保护，本项目独立实现） |
| 定朔定气之法 | 库外《时宪历》 |
| 干支纪日 | 儒略日 mod 60（连续日序，无断点） |

#### 4.1.2 算法

五个文件，逐层递进，**不使用任何历表**：

```
julian.js       公历 ↔ 儒略日（Fliegel–Van Flandern 整数式）、日序、星期
     ↓
astronomy.js    太阳视黄经（VSOP87 截断级数）
                日月合朔时刻（JDE 章级数）
                ΔT（Espenak–Meeus 多项式）
                力学时 ↔ 北京时换算
     ↓
solar-terms.js  以「圈号 + 相位」反解「视太阳黄经 = 节气度数」的时刻，精确到秒
     ↓
lunisolar.js    朔日定月
                「两冬至间 13 个朔月 → 第一个无中气月置闰；12 个则不闰」
     ↓
sexagenary.js   干支（儒略日 mod 60）
                节气换月、立春换年、五鼠遁时干
```

**为什么必须重算而不能查表**：查表法在边界日必错，而边界日恰恰是最需要准确的位置——闰月归属、交节换月都落在这些时刻上。表还有一个更根本的问题：覆盖范围外直接失效，且无法回答「为什么这天是闰月初一」。

**四条干支口径铁律**（写死在代码里，不开放配置）：

| 项 | 规则 |
|---|---|
| 年界 | 立春交节时刻 |
| 月界 | 节气交节 |
| 日界 | 子时子初（23:00）换日 |
| 生肖 | 随年柱支 |
| 时干 | 由日干五鼠遁现算：`时干 = (日干序×2 + 时支序) % 10` |

#### 4.1.3 能给出什么结果

| 能力 | 精度 / 覆盖 |
|---|---|
| 公历 ↔ 儒略日 | 整数运算，无累积误差 |
| 节气时刻 | 精确到秒；1901–2049 全量 3,576 个节气对拍：平均偏差 0 秒、中位 0 秒、p99 = 1 秒、最大 60 秒、日期全同 |
| 农历月日、闰月 | 1901–2100 全量 73,049 天与参照实现零差异 |
| 干支四柱 | 年月日时四组，含换日换年边界处理 |
| 生肖、星期、节日、法定假期 | 生肖随年柱；节日依库外岁时记与现行法定名录 |

#### 4.1.4 一个刻意保留的边界约定

**交节时刻与出生时刻相等时，按「未交」处理。**

原因：参照实现在展示层把交节时刻四舍五入到分，而交节秒残差普遍为正，因此「出生恰等于该分钟」实际仍在交节之前。本项目在比较前先补零秒位再比字符串，避免 `'22:00:0' < '22:00:00'` 这种伪先后。

**晚子时的年界**：年柱与月柱按「原始出生时刻」判立春与交节（例如 1901-2-3 23 时，日柱已换至 2-4，但立春未到，年柱仍是上一年庚子）；日柱照常 23:00 换日；时干用换日后的日干五鼠遁现算。

#### 4.1.5 强度

**A（天文部分）**。天文级数是纯数学，可独立验证；对拍 3,576 个节气全部命中。

**算法**

建除十二神按**日支与月建支之差**定值，不按日序推支：

```
索引 = (日支 − 月建支) mod 12
序列 = 建 除 满 平 定 执 破 危 成 收 开 闭
```

依《协纪》原文「从月建上起建……如正月建寅则寅日起建顺行十二辰」。原实现误用「日序 mod 12」推支，已改。

黄黑道十二神：青龙/明堂/金匮/天德/玉堂/司命为黄道，余六为黑道。144 格逐格按原文复算——「青龙正月起子、金匮正月起辰、司命正月起戌（顺行六阳辰）；明堂正月起丑、天德正月起巳、玉堂正月起未（顺行六阴辰）」——不符 0 条，有守护断言。

**吉神凶煞的历例复算**：共 **43 神**由《协纪辨方书·卷九·立成》「日神取一定干支者」段逐条推得，含天恩、鸣吠、鸣吠对、五合、除神、解神、八专、触水龙、重日等。**有意不推的六神**：宝日、义日、制日、专日、伐日、无禄——立成虽有定干支，但通书「吉神宜趋／凶煞宜忌」两栏从不列它们（2024 全年 336 天实测 0 次），推出来只会拉低比对命中率并误导读盘者。

**依据**：《奇门遁甲统宗·附日奇门起例》原文。

> 「冬至后用阳遁，夏至后用阴遁，子午日用二局，余仿此。丑未日用六局，寅申日用一局，卯酉日用八局，辰戌日用四局，巳亥日用九局。其起九星八门之法不必复分阴遁阳遁。凡甲子日天蓬起艮八宫，芮在离九，顺飞九宫。乙丑日天蓬起离九，天芮在坎一。一日顺移其八门，则甲子日休门起坎一。三日顺转一宫，不入中五。」

**能给出什么结果**：三传四课结构化、毕法条目检出（95 条）、每条的原文依据。

## 五、核心亮点

以下七条均可复现验证。每条给出名称、价值、实现方式、与常见方案的差异，以及支持它的证据。

### 亮点一：历法自底向上重算，不查历表

- **亮点名称**：天文级数实时求朔。
- **价值**：解决「边界日必错」的问题。闰月归属、交节换月都落在朔日与节气时刻的边界上，历表在这些位置最容易出错，而错误会向下游所有模块传导。
- **实现方式**：公历 → 儒略日 → 太阳黄经（VSOP87 截断级数 + 章动/光行差/ΔT）→ 日月合朔（1985 年前走寿星精密朔表 `SHUO_KB`，之后走级数）→ 朔日定月 → 两冬至间无中气置闰。
- **差异化**：常见开源实现直接内嵌一份历表（或依赖第三方包），在表的覆盖范围外失效，且无法回答「为什么这天是闰月初一」。本方案每一步都可打印中间量。
- **证据**：节气精确到秒——1901–2049 共 3,576 个节气与高精度参照对拍，平均偏差 0 秒、p99 = 1 秒、最大 60 秒、日期全部一致。闰月命中：2004/2023 闰二月、2020 闰四月、1984 闰十月、1903 闰五月、1914 旧年代朔日全部正确；1985 无闰（正月初一 = 2 月 20 日）。

### 亮点二：全部算法自研，零第三方内嵌

- **亮点名称**：内核零内嵌依赖。
- **价值**：解决「不知道结果从哪来」的问题。内嵌第三方发行包意味着内核里有一块无法审计、无法按文献校改的区域。
- **实现方式**：5.0.0 重构前，内核曾内嵌第三方历法/紫微发行包；重构后**全部移除**。农历、干支、节气、紫微安星、奇门、六壬、六爻、梅花、飞星均为本项目独立实现，内核 61 文件 12,518 行。
- **差异化**：多数开源项目以「集成多个库」为能力证明，本项目相反——**依赖数量是负债，不是资产**。参考过的项目在 NOTICE 中逐条声明，只参考思路与规则，不复制代码与数据。
- **证据**：`package.json` 的 `dependencies` 为空；`npm test` 的 1,472 项断言全部在本仓库内实现，无测试框架依赖。

### 亮点三：算法以古籍原文为准，536 万例回归对拍

- **亮点名称**：以文献为准的校正机制。
- **价值**：解决「以既有实现为准」的循环论证。若把某个流行软件的输出当作标准答案，错误会被继承并放大。
- **实现方式**：**正确性以文献为准，不以任何既有实现为准**。凡库内 20 部公版古籍有明文者，一律按原文改判：

| 项目 | 改动依据 |
|---|---|
| 身强弱 | 改《滴天髓》得时/得地/得势三要素 |
| 扶抑方向 | 改《子平真诠》「强者抑之」 |
| 格局派用神 | 补顺逆用 |
| 天乙/文昌/羊刃/孤鸾/四废 | 按《三命通会》改正 |
| 调候 | 逐条对《穷通宝鉴》核改 13 条 |
| 巳藏干 | 改「丙戊庚」 |
| 纳音 | 改「沙中金」 |
| 外格专旺/从格 | 按《滴天髓·独象》《顺逆》原文判 |
| 奇门 | 补「时干入墓」并分层「三奇合吉门/三奇得使」 |

- **差异化**：文献无载者（太极贵人/金舆/红艳煞）如实标注「待考」，不伪装有据。逐条出处见 `docs/CALIBER-NOTES.md`「文献校正」节；22 项功能的证据强度总表见 `docs/EVIDENCE-MAP.md`（原书直证 / 结构自洽 / 库外通行三档）。
- **证据**：1901–2100 全日期 × 十二时辰回归对拍，证明重构未引入回归——八字 876,588 例、大运 1,753,176 例、紫微 1,779,456 例、奇门全家 876,588 例、黄历与农历转换 73,049 天全字段、八宅 596 例，合计约 536 万例。逐项记录见 `docs/COMPARISON-REPORT.md`。

### 亮点四：口径显式化，分歧点名

- **亮点名称**：口径单一真源。
- **价值**：解决「同一张盘两个答案」的问题。流派分歧本身不是缺陷，不声明才是。
- **实现方式**：紫微闰月归属（十五含在本月）、四化取中州主流、奇门取拆补定元、六壬昼夜贵人取卯至申、刻家取一时辰十刻（一刻十二分钟）——每一条都在 `docs/CALIBER-NOTES.md` 里写明，并注明「另派如何」。
- **差异化**：常见做法是把口径散落在代码注释里，改一处忘一处。本方案把口径集中成一张表，**改动口径 = 改动单一表**，不藏逻辑。
- **证据**：`npm run check:cites` 做文献引用审计，把《书名·篇名》逐条回到 `refs-texts/` 底本核对，引用不上的直接报错。

### 亮点五：大功能拆小模块，全项目模块化

- **亮点名称**：按「家」拆分的模块边界。
- **价值**：解决「一个文件两千行、改一处不敢动」的问题。
- **实现方式**：奇门按「家」拆在 `src/core/mystic-gates/` 下——`hour-chart.js`（时家转盘）、`day-chart.js`（日家）、`quarter-chart.js`（刻家）、`mirror-chart.js`（宝鉴日奇）、`year-month-chart.js`（年家月家）、`flying-chart.js`（飞盘）、`patterns.js`（格局）。六壬在 `src/core/six-ren/` 下——`tables.js` / `three-transmissions.js` / `heavenly-generals.js` / `bifa.js` / `chart.js`。
- **差异化**：按「术数门类」拆而不是按「技术层次」拆，每个文件单一职责、可单独测试。
- **证据**：每个模块都有对应断言，`tests/core.test.js` 单文件 1,190 项。

### 亮点六：三端共用一套内核

- **亮点名称**：内核不感知端。
- **价值**：解决「网页版对、小程序错」的问题。三端各写一份算法，结果必然分叉。
- **实现方式**：小程序把 ESM 逐文件转写为 CommonJS（`tools/build-mp.js`），PWA 直接把 ESM 放到站点根目录（`tools/build-web.js`），uni-app 复用同一批模块。
- **差异化**：产物一致性由 `npm run check` 逐文件比对——不是「相信它们一致」，而是每次构建都验。
- **证据**：`npm run check` 十二项发布自检，含逐文件产物比对。

### 亮点七：可直接托管，网页版就在仓库根目录

- **亮点名称**：零配置部署。
- **价值**：解决「克隆下来还得配构建目录」的问题。
- **实现方式**：`npm run build:web` 产出 `index.html` / `static/` / `core/` / `shared/` 到仓库根目录。
- **差异化**：EdgeOne 等静态托管平台连接仓库即可自动部署，无需指定构建命令与输出目录。
- **证据**：<https://x.ntars.cn/> 即由仓库根目录直接托管。

## 六、设计细节与小巧思

### 5.1 输入归一化：九种写法收敛到同一盘

`src/core/features/normalizer.js` 处理以下差异，使九种写法 `1990年6月15日` / `1990-6-15` / `1990.6.15` / `1990/6/15` / `15/6/1990` / `19900615` / 含零宽字符 / 全角 / 中文数字 得到同一张盘：

| 处理项 | 具体做法 | 为什么必须处理 |
|---|---|---|
| 零宽与 BOM | 直接清零宽空格与 BOM | 从网页复制的日期常带零宽字符，肉眼不可见却会让解析失败 |
| 全角与花式数字 | 全角数字转半角；上标下标转普通数字 | 中文输入法下全角数字极常见 |
| 英文月份 | `Jan`/`January` 等转数字 | 用户从英文材料复制 |
| 中文数字 | 转阿拉伯数字，**但 60 余条功能词占位保护不被数字化** | 「排八字」「三奇」里的数字是功能词，数字化会破坏匹配 |
| 分隔符 | `年/月/日`、`-`、`.`、`/`、空格统一 | 写法太多，逐种判断不可维护 |
| 连续数字拆分 | 按 14/12/8 位日期时间、6 位 YYMMDD、倒序 D-M-Y、日期后 HHMM、孤立 MMDD 拆分；**9–11 位视为身份证不拆** | 19900615 是日期，440101199006151234 是身份证，长度是唯一可靠判据 |

### 5.2 缺省与拒绝的边界

- 缺时辰补 14 时：命理类功能必须有四柱，缺时辰时取未时而非报错，因为大多数用户不知道自己的时辰。
- 命理类缺生辰走四拒绝码就地提示（`need_birth` / `invalid_lunar` / `invalid_pillar` / `invalid_solar`），不猜。
- 查询类（今日黄历、查农历）不受生辰限制：查今天不需要知道自己的生日。

### 5.3 结果页三分支

| 分支 | 触发条件 | 排版 |
|---|---|---|
| 单算法 | 一句话只命中一个功能 | 单栏结果 |
| 多命中并列 | 命中多个功能（如「八字 紫微」） | 每节 `{title, text}` 并列 |
| 全套排盘 | 只给生辰不给功能名 | 七类分组 |

统一「标签：值」两栏排版，长值自动折行。

### 5.4 存储三承诺

1. **读取不抛错**：任何存储读取失败都返回默认值，不让异常冒到界面。
2. **缺失给默认值**：键不存在时给默认，不给 `undefined`。
3. **只清本项目前缀**（`xael_`）：清缓存不会误删同域其他应用的数据。

上限 1MB。超限时按最旧优先淘汰，不静默失败。

### 5.5 错误守卫

只监听 `window` 的 `error` 与 `unhandledrejection`，三条纪律：

- **不吞错**：记录后仍让控制台可见；
- **不外泄堆栈**：上报内容不含文件路径与调用栈；
- **带频控**：同一错误 60 秒内只报一次，避免循环错误刷屏。

### 5.6 离线三级兜底

Service Worker 的请求处理顺序：网络 → 缓存 → 离线页。`404.html` 零外部请求——离线页若引用了 CDN 资源，断网时它自己也打不开。

### 5.7 视觉与单位纪律

- 深浅主题 320ms 交叉过渡，手动优先于系统，小程序端同步 `wx.setBackgroundColor`；
- 响应式四档：<360px 满宽、360–767 设计稿、768–1023 居中 640、≥1024 居中 720，字号恒定；
- 单位一律 px / rem，**不使用 rpx**（uni-app 端如需条件编译适配小程序尺寸，见 `docs/DEPLOY.md`）；
- 开屏 1.2s 停留 + 400ms 缩放交接；按压 120ms；弹窗「先播后摘」；
- 导出图片：结果页镜像排版，2 倍图，单页超 4096pt 自动分页并标注「(接上页)」「第 i/n 张」。

## 十六、已知问题与限制

1. **流派分歧极大处各取一种**：刻家、宝鉴日奇、年家月家、飞盘的流派分歧极大，本项目各取一种写明口径，不保证与商业软件一致。
2. **毕法赋 100 法中 95 条可判**：其余 5 条（93/97/98/99/100）注文为断课方法论、无独立盘面判据，只列目录不臆造；第 56 条须占人本命才可能命中。
3. **奇门格局按十干克应检出典型格**：未收录条目一律不生成，宁缺不臆造。
4. **节假日数据有截止**：截至 2026 年国务院公告，之后年份需随源码更新。
5. **天文算法与《中国天文年历》存在秒级差异**：对术数应用无影响，但不宜用于天文观测。
6. **文献待考项**：太极贵人、金舆、红艳煞三项文献无载，标注「待考」而非伪装有据。
